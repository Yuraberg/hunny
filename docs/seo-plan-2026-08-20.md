- Canonical, robots-мета, OG/Twitter на всех страницах (`BaseLayout.astro`).
- JSON-LD: `Store` + `WebSite` глобально, `Product` на главной, `Article`/`BlogPosting` + `BreadcrumbList` в вики и историях.
- Sitemap с фильтром заглушек, robots.txt со ссылкой на sitemap.
- 573 полноценные статьи энциклопедии — большой контентный актив.

**Мешает (сгруппировано по тяжести):**

## 1. Фундамент и наблюдаемость (неделя 1)

Без этого остальное измерять нечем.

1. **Яндекс.Метрика** — счётчик в `BaseLayout.astro`, включить Вебвизор, карту скроллинга, отчёты по электронной коммерции (`dataLayer` на добавление в корзину и `/order/thanks`). Для Яндекса поведенческие — один из сильнейших факторов; сейчас их просто нечем измерять и нечем улучшать.
2. **Яндекс.Вебмастер** — подтвердить домен, отправить sitemap, включить обход по счётчику Метрики, задать регион **Самара / Самарская область** (без региона коммерческие запросы «мёд Самара» не ранжируются), проверить «Диагностику» и «Мониторинг важных страниц».
3. **Google Search Console** — подтвердить домен (property на уровне домена), отправить sitemap, следить за Core Web Vitals и «Индексирование страниц».
4. **IndexNow** — Яндекс и Bing поддерживают; при 573+ страницах и регулярных обновлениях даёт быструю переиндексацию. Реализация: ключ-файл в `public/`, шаг в `deploy.yml` — после успешного деплоя отправлять изменённые URL (git diff по `dist/`).
5. **Google Analytics 4** — опционально, если нужен второй источник данных; Метрика для РФ важнее.

**Критерий готовности:** обе панели зелёные, sitemap принят, трафик виден в Метрике.

## 2. Критические технические правки (недели 1–3)

### 2.1. Убить заглушки энциклопедии (приоритет №1 по технике)

Сейчас: 1432 HTML-страницы «статья скоро появится» + внутренние ссылки на них из настоящих статей (`[Мёд](/wiki/med)` и т.п.). Они исключены из sitemap и закрыты `noindex`, но роботы всё равно их обходят и получают сигнал «сайт на 70% состоит из пустых страниц».

Правильный фикс — не генерировать их вовсе, но тогда внутренние ссылки станут 404. Порядок:
1. rehype-плагин на рендер вики: если ссылка ведёт на `/wiki/<slug>`, которого нет в коллекции, — рендерить как обычный текст (или `<span>` с подсказкой), а не `<a>`.
2. Удалить `stubPaths` из `getStaticPaths` и `wiki-stubs.json` из `astro.config.mjs`.
3. Уже проиндексированные заглушки (если такие есть) отдать 410 или 301 на `/wiki`.

Итог: 2006 → 574 страницы вики, все — содержательные.

### 2.2. Товарные страницы `/catalog/[slug]`

Каждому мёду — свой URL с уникальным текстом (300–600 слов): происхождение, вкус/аромат, кристаллизация, с чем сочетается, как хранить, фасовка, цена, доставка, ссылки на связанные статьи вики.

Разметка `Product` на странице товара (сейчас она свалена на главную «пачкой», без `url`):
```
Product: name, description, image[], sku, brand, url,
offers: { price, priceCurrency: RUB, priceValidUntil, availability,
          url, seller: @id, shippingDetails, hasMerchantReturnPolicy }
```
`aggregateRating`/`review` — только когда появятся реальные отзывы. Фейковые рейтинги в разметке ловят и Google, и Яндекс.

Плюс страница-хаб `/catalog` (`ItemList` + `BreadcrumbList`) — она и будет целевой под «купить мёд с пасеки».

### 2.3. Изображения и шрифты (Core Web Vitals)

- `ProductCard.astro:19` → компонент `<Image>` (или `<Picture>`) с явными `width`/`height`, `format="webp"`, `loading="lazy"`, `decoding="async"`. Сейчас в прод уходит оригинальный JPEG вместо готового 40 КБ webp, который Astro уже собирает.
- Первый экран (`Hero`, `JarFlip`): `loading="eager"` + `fetchpriority="high"` для LCP-элемента.
- Google Fonts → self-host через `@fontsource/*`, `font-display: swap`, preload основного начертания. Убирает внешний render-blocking запрос и снимает риск недоступности CDN в РФ.
- Caddy: `Cache-Control: public, max-age=31536000, immutable` для `/_astro/*`, короткий для HTML; brotli.

**Цель:** LCP < 2.5 с и CLS < 0.1 на мобильных, в GSC — «Хорошо» по всем URL.

### 2.4. Мелочи индексации

- Sitemap: исключить `/order/*`, добавить `lastmod` через `serialize` (Яндекс его использует при планировании обхода).
- robots.txt: `Disallow: /order/`, `Clean-param: utm_source&utm_medium&utm_campaign&yclid&gclid` (директива для Яндекса — склеивает URL с метками).
- OG: для статей и историй `og:type: article` вместо `website`; для товаров — `product`.
- Хлебные крошки визуально (не только в JSON-LD) на вики, историях, товарах.

### Информационные (трафик + E-E-A-T, уже частично закрыты вики)

- Сорта: чем отличается гречишный от липового, какой мёд самый полезный, тёмные сорта.

`/catalog`, `/catalog/[slug]`, `/dostavka-i-oplata`, `/kontakty` (карта, реквизиты ИП/ОГРНИП, схема проезда), `/o-paseke` (история, фото, люди — база E-E-A-T), `/otzyvy`, `/wiki/category/[slug]` (9 категорийных хабов — сейчас 573 статьи висят на одном плоском индексе, глубина вложенности и распределение веса плохие).

## 4. Контент энциклопедии: снять риск, конвертировать в трафик

573 статьи — главный актив и одновременно главный риск. Google с марта 2024 прямо считает нарушением масштабную генерацию контента без добавленной ценности; Яндекс фильтрует малополезный текст и переоптимизацию.

**Что делать (порядок важен):**

1. **Медицинские схемы — вычистить в первую очередь.** 63 файла содержат дозировки и схемы приёма («50–100 г/сутки в течение 2–3 месяцев», «при гастрите за 1,5–2 часа до еды»). Это (а) YMYL-контент от неэксперта, (б) риск претензий по рекламе продуктов с заявленными лечебными свойствами. Заменить на нейтральные формулировки («традиционно применяется», без дозировок), добавить дисклеймер-блок «не является медицинской рекомендацией, проконсультируйтесь с врачом» и вывести его в шаблон `wiki/[slug].astro`.
2. **Приоритизировать 50–80 статей** под реальный спрос (сорта мёда, натуральность, хранение) и довести их вручную: авторская вычитка, факты со ссылками на ГОСТ/Codex/исследования, фото с пасеки, блок «мнение пасечника», FAQ-блок + `FAQPage`-разметка.
3. **Автор и экспертиза.** Страница автора (`Person` с описанием опыта Дмитрия Бердникова), поле `author` + `datePublished`/`dateModified` в схеме вики (сейчас их нет — есть только в историях).
4. **Остальной массив** — не удалять, но и не пушить: оставить в индексе, следить в GSC/Вебмастере. Если по кластеру пойдут отказы и «малополезный контент» — резать пачками.
5. **Перелинковка:** из статьи о сорте → на товар этого сорта, из товара → на 3–5 статей. Это и трафик, и коммерческий сигнал.

## 5. Локальное SEO (Яндекс здесь даёт больше всего)

- **Яндекс Бизнес** — карточка организации: адрес/зона обслуживания, телефон, часы, фото пасеки и продукции, товары с ценами, ссылка на сайт. Отображение в Картах и в выдаче по «мёд Самара».
- **Google Business Profile** — тот же набор.
- **Отзывы** — системно просить после заказа (SMS/письмо со ссылкой на карточку Яндекса). Для Яндекса отзывы и рейтинг на Картах влияют и на локальную выдачу, и на кликабельность.
- **Справочники и агрегаторы:** 2ГИС, Zoon, Флэмп, отраслевые каталоги пчеловодов. NAP (название-адрес-телефон) — строго одинаковый везде.
- В `Store`-схеме добавить `geo` (координаты), `openingHours`, `sameAs` (VK, Telegram), `hasOfferCatalog`.

## 6. Коммерческие факторы (специфика Яндекса)

Яндекс явно оценивает «магазинность» сайта. Чек-лист:

- [ ] Цены на всех товарах, без «уточняйте»
- [ ] Отдельная страница доставки со сроками, зонами и стоимостью
- [ ] Способы оплаты (ЮKassa уже есть — описать)
- [ ] Реквизиты: ИП, ИНН, ОГРНИП в футере и на `/kontakty`
- [ ] Телефон + мессенджеры, время работы
- [ ] Условия возврата / гарантия качества
- [ ] Реальные фото производства и людей (не сток)
- [ ] Политика конфиденциальности — заполненная под 152-ФЗ (сейчас шаблон, см. аудит от 13.08)
- [ ] Отзывы покупателей на сайте
- [ ] YML-фид «Товары и цены» в Яндекс.Вебмастере
- [ ] Google Merchant Center → бесплатные товарные листинги

## 7. Внешние сигналы (в основном под Google)

Без ссылочного Google не даст конкурентные коммерческие запросы. Безопасные источники для локального фермерского бренда:

- Локальная пресса и городские паблики Самары («семейная пасека» — хороший инфоповод).
- Гастрономические блоги, крафтовые маркетплейсы, фермерские кооперативы.
- Отраслевые каталоги пчеловодства.
- VK/Telegram/Дзен с перелинковкой на статьи вики (Дзен даёт и прямой трафик, и сигналы Яндексу).
- Гостевые материалы на тему «как отличить настоящий мёд» — контент уже есть, его надо переупаковывать.

Чего не делать: биржи ссылок, прогоны, сетки сателлитов — под Минусинск/Пингвин.

## 8. Дорожная карта

**Недели 1–2 — фундамент**
Метрика + Вебмастер + GSC + регион; IndexNow; sitemap/robots; noindex-мелочи; исправить `<img>` в ProductCard; self-host шрифтов.

**Недели 3–6 — коммерческое ядро**
`/catalog` + страницы товаров с `Product`-разметкой; `/dostavka-i-oplata`, `/kontakty`, `/o-paseke`; H1 и тексты главной под запросы; карточки в Яндекс Бизнес и GBP; YML-фид.

**Недели 4–8 — санитария контента**
Убрать заглушки вики (rehype + удаление генерации); вычистить 63 статьи с медицинскими схемами; дисклеймер и автор в шаблоне; категорийные хабы вики.

**Месяцы 3–4 — качество и перелинковка**
Довести вручную 50–80 приоритетных статей; FAQ-разметка; связки статья ↔ товар; сбор отзывов; первые внешние публикации.

**Месяцы 5–6 — масштабирование**
Разбор GSC/Вебмастера по запросам, добор кластеров, сезонные посадочные (подарки к НГ, «мёд к чаю осенью»), Merchant Center, работа с CTR (title/description по данным выдачи).

## 10. Что учесть из аудита 13.08.2026

Пересекается с SEO напрямую:
- Незаполненная `privacy.html` — это и 152-ФЗ, и коммерческий фактор Яндекса.
- Отсутствие CSP/безопасных заголовков — на ранжирование не влияет, но заодно закрывается при настройке Caddy под кэш-заголовки.
- Вики рендерит raw HTML из LLM-контента без `rehype-sanitize` — тот же rehype-пайплайн, что и для фикса ссылок-заглушек (§2.1); имеет смысл сделать за один заход.
