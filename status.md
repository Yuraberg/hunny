## CMS/CRM (обсуждали отдельно от SEO-плана)

- **CMS**: решили не внедрять — контент редактирует только разработчик, git + Astro Content Collections остаются источником правды. Decap CMS как тонкая визуальная надстройка — вариант на будущее, если появится нетехнический редактор.
- **CRM**: рекомендация — **EspoCRM** (self-hosted/бесплатно, есть модуль Campaigns под рассылки). Отклонены Odoo (слишком тяжёлый ERP для масштаба проекта) и Twenty (маркетинг-модуль недостаточно зрелый на момент оценки, надо перепроверять перед выбором). **Установка не начата** — ждали проверки свободных ресурсов VPS (RAM/диск), доступа не было.

**Что работает:**
- Паттерн на каждый пункт плана: сделать → `npm run build` локально → если страница/визуал — dev-сервер + браузер-проверка (клик по кнопкам, JSON-LD парсится, network requests) → закоммитить только релевантные файлы (не `git add -A`, в рабочем дереве всегда есть посторонний untracked мусор — `Gemini/`, `honey-wiki/__pycache__/`) → спросить подтверждение → push → дождаться `gh run view` до `status=completed` → проверить `curl` на живом домене.
- Ручной триггер деплоя без нового коммита: `gh workflow run deploy.yml -R Yuraberg/hunny` (использовали, когда меняли только secrets).
- Monitor-обёртки вокруг `gh run view` периодически падают сами по себе (баг в моём же bash-цикле) — это **не** значит, что деплой упал; всегда перепроверять `gh run view <id> --json status,conclusion` напрямую.
